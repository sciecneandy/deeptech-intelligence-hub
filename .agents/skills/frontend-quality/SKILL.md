# Frontend quality

1. Understand the product, audience, existing design system, and framework before changing the interface. Match established patterns unless the task calls for a new direction.
2. Build clear visual hierarchy and responsive layouts. Handle relevant loading, empty, error, success, and interaction states.
3. Use semantic HTML, accessible names, keyboard operation, visible focus, and sufficient contrast. Respect reduced-motion preferences when adding motion.
4. Verify with appropriate project checks and, when feasible, inspect the running interface at representative desktop and mobile widths. Exercise key interactions and report any verification limits.
